# Animation Workshop Evolver

A prompt-and-configuration method for reusable web-physics animation capabilities. This transfer-oriented revision treats the current task as a learning case, not the adapter's identity. It has no MWM lifecycle or mandatory world-fact schema.

The Evolver separates reusable behavior from scene-specific geometry, coordinates and presentation; develops concrete methods, inspectable implementations and integration examples; and identifies the behavior an actor should preserve and check after adaptation. Full scenes remain useful examples, but the default briefing routes by capability rather than recommending the latest task answer.

Within the available budget, it checks the observed failure and one structurally different diagnostic case. A self-authored variation is development evidence, not held-out evaluation or a transfer score. Missing checks must remain explicit. Existing scene-centered adapters can be refactored incrementally without deleting historical examples or introducing a mandatory engine/API.

Usage: `harnessadapter evolve --architecture animation-workshop --evolver animation-workshop --learning-material PATH --model gpt-5.6-sol --reasoning-effort high --output OUTSIDE_CHECKOUT`.

Visual trials require an explicitly bound external renderer. The broker snapshots requests and exposes read-only observations; it does not render them itself. A caller may use the Codex in-app browser outside the learner sandbox. Budget repairs and structural-variation checks explicitly, and identify the final revision actually rendered. A request alone is not a completed visual check.

Changing this preset affects future sessions. Previously evolved adapters and recorded method snapshots are not automatically rewritten, and this prompt change alone does not demonstrate transferability.
