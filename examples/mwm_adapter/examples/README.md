One graded episode per file, named for its address.
This is what every `derived_from:` in the model points at, so the FILENAME
is the address, in the record-address form "This environment" states
(`<record-address>.md`). A host that follows an address from the briefing
lands here and must find the episode whole — what it was given, what
decided it, what it did, and what the environment's feedback was. Keep
correct episodes too: a verified worked example is the strongest evidence
a rule can carry.

Writing one (the template is _template.md):
- Keep the input's distinctive nouns VERBATIM: they are the signature a
  future episode of the same family is found by. Before writing, grep the
  model for that signature — an example of the family may already exist.
- Decisive is the interpretation choices that settled it — which reading
  of the input, which boundary, which tie-break rule, and why; Skeleton is
  the accepted action or computation trimmed to its decisive shape.
- When the episode was wrong and the environment revealed the accepted
  answer, Feedback states what that answer implies about the environment,
  worded so the next solver can apply the correction directly.
- A briefing claim indexes; the example grounds. Where a claim generalises
  several examples, link them with [[...]] so a host can pull the worked
  example behind the rule instead of trusting the summary sentence.
