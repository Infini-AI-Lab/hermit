## 2. 关键发现

1. **证据其实就在眼前**：97/103 的失败里，正确的表/行/期曾出现在 GLM 自己的输出中（57 完全、40 部分）；
   85/103 在分叉点 GLM 自己表达过怀疑。瓶颈不是「找不到」，而是「选错了却不核对」。
2. **文字经验基本没被执行**：prompt 组 33 个失败里 32 个上下文中有相关条目，只有 2 个完整照做
   （部分 21、没做 8）；其中 10 个条目本身完全正确。19/33 文字「可能/确实」参与导致错误。
   cards 组 16/39 由卡片「可能/确实」导致（C003/C007 「用最新一期」越界、C021 列规则串题、C009 ×100）。
3. **首选补救层级**：CHECK 41、TOOL 31、CONTROL 23、TEXT 6、STATE 2。
   补救的通用性：document-QA 通用 178、领域通用 105、OfficeQA 专属 56（按条目计）。
4. **运行层问题很重**：失败 run 中 27 个严重打转、39 个轻度打转；26 个提到上下文压缩（compaction）
   把已验证的中间结果冲掉或改写。全体运行：命令数最多的四分之一只对 6/34、5/34、7/34。
5. **环境缺陷（对所有组都成立）**：
   - zsh heredoc 失败（沙盒禁写 `/tmp`，而 zsh 用 `TMPPREFIX` 不用 `TMPDIR`）：none 131/133 题、cards 133/133 题碰到；
   - `rg` 被沙盒拒绝；`python3` 触发 Xcode 报错（只有 `python` 可用）；GLM 的 Python 无 numpy；
   - Codex 把长命令输出截到 ~10 KB（头+尾），模型看不到中间的表行（Q9）；
   - 读权限过宽：13 个 run 做过全盘搜索，3 个列出了同组其他题的目录（均未打开，均答错，成绩不受影响）。
6. **反向 17 题的教训**：Opus 常常已算出正确候选再推理着放弃；GLM 答对多靠固定规则/运气。
   没有一条「版本规则」能覆盖所有 key（Q4 用最新、Q36/Q85 不是）→ 要把「多版本不一致」显式摆出来 + 固定的决胜顺序；
   复核者不能在没有具体错误的情况下推翻解题者（Q37）；来自 issue-47 争议题的经验要隔离（Q36 → L-ifs1-monthly-first-printing）。

## 4. 结论：做新的「机制型」adapter，而不是继续改 cards

cards 的根问题是「纯文字 + 每题展示整副牌」：文字不被执行、还会越界。保留它的好想法
（scope/unless 触发条件、带对照的验证、命中账本），但把载体从文字换成**可执行的机制**。

### v9 Mechanism Adapter（草案）

- **L0 环境修复（所有组都修，保证基线干净）**：`TMPPREFIX`、`python3`、numpy、`rg`、读权限收窄、分页输出不静默截断。
- **L1 工具**（workspace CLI，document-QA 通用）：`find_tables`（标题/表头短语检索，大小写归一）、
  `show_table`（干净网格：表头对齐、每行补全年月、明示行数）、`printings`（同一行在所有期号的数值+as-of+p/r 标记）、
  `calc`（带 numpy 的脚本执行并记账）；可选 `ref`（外部参考序列，需决定是否允许）。
- **L2 账本 ledger**：`ledger cell --src file:line …`、`ledger candidate --reading …`；每次上下文压缩后由 broker 重新注入。
- **L3 流程控制（在我们自己的 broker 里实现）**：重复命令 ≥3 次注入提醒+当前候选；时间过半要求先记一个候选；
  超时提交账本里最好的候选而不是空答案。
- **L4 提交闸门（checkers）**：模型给出最终答案时先跑检查——格式/缩放、答案=某次 calc 输出、引用值确在所引行、
  期间标签匹配、存在更新版本且值不同则要求写明取舍、分项和=合计；不通过就把具体信息反馈给模型一轮（最多 2 轮），
  模型可修正或写理由覆盖（记录在案）。复核只能凭「某项检查失败/具体错误」改答案。
- **L5 少量文字**：短流程 + 按触发条件检索的 scoped notes（不再整副展示）。

### 进化器（为什么能比纯文字 evolve 更强）

学习者每 5 题看到与 prompt 学习者相同的反馈，但能改的是：checker（带触发条件的 Python 判定）、工具（解析器/选项）、
控制参数、scoped notes。**准入测试是离线回放**：新 checker 在所有历史 episode 的账本/轨迹上确定性地跑一遍，
必须命中它要修的失败、且在答对的 episode 上几乎不误报——零 GLM 成本、没有 27% 重跑翻转噪声。文字经验做不到这一点。

三个结构性优势（都有本分析的数据支撑）：执行力（文字只被完整照做 2/32）、可离线验证（checker 的精度可直接量）、
有触发范围（不像整副卡片那样越界）。

### 公平实验（待用户确认）

- 组：none、prompt-evolve（v8 同款）、mech-static（v9 初始，不学习）、mech-evolve（v9 + 进化器）。
  static vs evolve 证明「进化」本身有用；mech-evolve vs prompt-evolve 证明「机制 > 文字」。
- L0 环境修复对所有组生效。
- 可信度：v9 初始内容不得含 OfficeQA 专属知识（审计）；同一架构再跑一个没被分析过的基准（DocVQA / Spreadsheet）；
  如需 OfficeQA 留出集，要下载 HF 上非 Pro 的题（答案公开可见，需用户决定）。
- 噪声：对照重跑翻转率 ~27%，单次 133 题的配对差 SD 约 ±6 题 → 每组至少 2 次，或只认 ≥10 题的差距。
- 先做零成本的离线回放：把能在 v8 轨迹上直接判定的 checker（格式/缩放、答案是否来自执行过的计算、打转）跑一遍，估算覆盖率和误报率，再决定付费实验。
