# OfficeQA Pro 50 — full profiles, unbounded inference, checked postmortems

Two paired arms use the exact same ordered 50 questions, pinned dataset, 697
parsed TXT documents, retrieval helper, native Codex and exact Fireworks
`accounts/fireworks/models/glm-5p3-flash` model. Fresh generic W0 of the
selected architecture: no memory from previous OfficeQA experiments.
`learn_every = 5`. This protocol covers both full profiles:

- `full_mwm_unbounded` — the adapted arm receives the latest mechanically
  admitted MWM (memory, briefing, examples, tested tools, roles, wm MCP tool).
- `full_prompt_only_unbounded` — the adapted arm receives the latest admitted
  `ADAPTER.md`, served verbatim inside the actor's `AGENTS.md`. No MCP server,
  roles, executable tools or container exist in this profile.

The baseline has no adapter. Both arms have the same native Codex facilities and
provider settings. Learned instructions are adapter artifacts, never harness edits.

## Inference policy

- No actor/learner wall-clock deadline, cumulative token cap, request/tool count
  cap or cost cap. Fireworks `max_tokens`, `max_completion_tokens`,
  `max_output_tokens`, numeric reasoning budget and thinking budget are omitted.
  The provider chooses its default output/thinking behavior; its intrinsic
  windows and account-side limits are not removed by this code.
- Nothing is cut and no circuit breaker exists. Retries with accounting replace
  voids: Codex is configured with `request_max_retries = 100` and
  `stream_max_retries = 100`, its hard maximum (idle stream timeout one hour); the local broker
  re-sends a call whose stream dropped before any generation was observed
  (`transport_retry`, local backoff, no shared rate cooldown) and records every
  attempt. A drop after generation is terminal for that call and is left to
  Codex's own stream retry. Explicit pre-generation rate refusals retry with
  provider/backoff delays and no retry-count ceiling. `call_failures`,
  `wire_attempts`, `requests` and `rate_refusals` are counters in
  `api/summary.json`; only budget exhaustion (never enabled here) marks a call
  as failed.
- A question is empty only when Codex produced no completed turn. The terminal
  event (`turn.completed` / `turn.failed`) and the `turn.failed` error text are
  recorded per actor.
- `project_doc_max_bytes` is 4 MiB. The served `AGENTS.md` size is recorded per
  actor (`agents_md_bytes`) and audited against that limit; nothing is truncated.
- Lockstep: both arms advance one five-question block at a time so they face the
  same provider conditions. The learning round after Q50 is skipped (recorded as
  `skipped_unused`): no actor would consume it.
- The MWM briefing is served whole; the native 30,000-character figure is
  advisory and reported, not enforced. No 6,000-character cap is imposed.
- Codex and the learner may compact context and continue. Learner summaries are
  generated by the same GLM, with their own API usage recorded. Compaction is not
  an experiment token budget. Finite tool-output pages, executable-test timeouts
  and OS isolation are native tool mechanics, not budgets.

## Answer release and learning

Seal the five adapted submissions first, then release only those five reference
answers. Baseline outputs, future questions/answers, source mappings and prior
experiment artifacts are unavailable. Original submissions cannot be repaired
or rescored after learning.

For the sealed batch the controller also runs the pinned official grader and
gives the learner each episode's strict (tolerance 0) and 1% verdict together
with its failure record (`failure.json`: status, failure kind, terminal event,
error text, requests, wire attempts, call failures, elapsed seconds, served
AGENTS.md bytes and limit). Grades of unreleased batches, grader rationales and
the master key stay hidden. An optional reference shelf (extracted reference
text prepared with `launch.py prepare --shelf`) is readable by the learner only;
actors never receive it. Its hashes are frozen with the campaign.

The learner session is a controller-driven postmortem. Every strict-incorrect
episode gets one phase on the ladder S1 locate bulletin/vintage → S2 table or
section → S3 row/column/units → S4 extract cells (count them) → S5 formula or
convention → S6 format/round; S7 is a harness/runtime cause (transport, output
limit, loop). In each phase GLM diagnoses with new information (trajectory,
failure record, corpus, shelf), decomposes the failure into the ladder, verifies
each rung now, and records `scratch/postmortem/<nnn>.json` plus one lesson per
re-verified rung. Verification uses two controller-executed checkers:
`verify_cell(file, line, contains)` reads one corpus line through the same
helper the actors use; `verify_answer(ordinal, candidate)` grades a candidate
for a released ordinal only and returns strict/1% verdicts without rationale.

Lessons carry `status`, `scope`, `step`, `check` and `verified_by` fields. After
every session the controller replays each lesson's `check` list against the
corpus and the released references only; a lesson is `verified` iff its checks
are non-empty and all pass, otherwise it is demoted to `candidate`. MWM serves
only verified lessons (memory `L-*` entries listed in the Verified lessons
section). Prompt-only serves `ADAPTER.md` whole, so every lesson reaches the
actor carrying the status line the controller wrote; its procedure tells the
actor to apply only `status: verified` lessons. The replay result is recorded in
`control/postmortem-replay.json` and audited against the admitted candidate.

MWM: GLM can inspect traces, revisit the complete permitted document corpus,
execute local calculations and evolve every native MWM artifact layer. Learned
executable tools are callable only after their real sandboxed tests pass.
Prompt-only: GLM edits `ADAPTER.md` (procedure, conventions, lessons, open
questions) and Markdown notes; `adapter.json` and `EVOLVER.md` must not change.

Integrity, native static structure, normal model completion and GLM-only
provenance determine admission. There is no Markdown-only allowlist, mandatory
exhaustive trajectory-read gate, required knowledge change or semantic/score
selection. Missing postmortem records are reported, not failed. Native serving
code, policy, evidence and controller records remain immutable.

## Execution isolation

Actors keep the previous macOS whole-client Seatbelt isolation: only their own
task folder is writable, corpus/current adapter are read-only, and only their
own controller relay TCP port is reachable. The relay forwards model calls only
to fixed Fireworks inference.

MWM only: the relay also serves a fixed local executable bridge. Learned tools
execute through the upstream Linux PythonSandbox in an ephemeral networkless
local container that mounts only the current adapter read-only; no corpus,
official answers, host checkout, secrets or Docker socket is mounted. The actor
never receives Docker access. The image is pinned by digest at preparation.
Prompt-only: no container and no Docker inspection at preparation.

Learner commands use the native folder/network sandbox with explicit document
read grants (corpus, index, helper, postmortem directory, shelf). The whole
repository is excluded from runtime read grants because it may contain private
run directories. Commands cannot change the protected core, Git metadata,
scoring or policy. Only the candidate/scratch are writable.

## Scoring and interpretation

The pinned official grader runs twice: per sealed block, for the learner only
(strict and 1% verdicts of the five released episodes), and once on all 100
sealed original predictions at the end for the reported scores. Strict numeric
tolerance 0 is primary; 1% is secondary. No LLM judge. Round 10 is not run.
Failed attempts stay in the denominator. This compares two treatments within
this run. Multiple settings differ from the prior bounded memory-only
experiment, so cross-run changes cannot be attributed to any one setting. The
adapted arm receives additional compute, past answers and past grades. Costs
and unknown usage are recorded, not constrained. No paid score is claimed by
packaging, preflight or synthetic tests.
