# OfficeQA Pro 50 — full MWM, unbounded inference

Two new paired arms use the exact same ordered 50 questions, pinned dataset,
697 parsed TXT documents, retrieval helper, native Codex and exact Fireworks
`accounts/fireworks/models/glm-5p3-flash` model. Fresh generic W0: no memory from
previous OfficeQA experiments. `learn_every = 5`.

The baseline has no adapter. The adapted arm receives the latest mechanically
admitted MWM. Both have the same native Codex tool/delegation facilities and
provider settings. Learned role instructions are an adapter artifact.

## Inference policy

- No actor/learner wall-clock deadline, cumulative token cap, request/tool count
  cap or cost cap. Fireworks `max_tokens`, `max_completion_tokens`,
  `max_output_tokens`, numeric reasoning budget and thinking budget are omitted.
- The provider chooses its default output/thinking behavior. Its intrinsic
  context/output windows and account-side limits are not removed by this code.
- Explicit, pre-generation rate refusals retry with provider/backoff delays and
  no retry-count ceiling. Ambiguous failures or partially generated responses
  are recorded, not silently resampled. No alternate model.
- Codex and the learner may compact context and continue. Learner summaries are
  generated by the same GLM, with their own API usage recorded. Compaction is not
  an experiment token budget.
- Finite tool-output pages, executable-test timeouts and OS isolation are native
  tool mechanics, not Fireworks session budgets. The MWM native 30,000-character
  delivered briefing remains part of its architecture; no 6,000-character task
  write/admission cap is imposed.

## Answer release and learning

Seal the five adapted submissions first, then release only those five reference
answers. Baseline outputs, future questions/answers, source mappings, official
grader rationales and prior experiment artifacts are unavailable. Original
submissions cannot be repaired or rescored after learning.

GLM can inspect traces, revisit the complete permitted document corpus, execute
local calculations and evolve every native MWM artifact layer: memory, examples,
briefing, investigations, executable tools and role specifications. There is no
Markdown-only allowlist, mandatory exhaustive trajectory-read gate, required
knowledge change, feedback-format gate or semantic/score-improvement selection.
GLM is asked to record per-episode public feedback. Missing feedback is reported.
Native serving code, policy, evidence and controller records remain immutable.

Integrity, native static structure, normal model completion and GLM-only tool
provenance determine admission. Native MWM advice/gates are recorded. Learned
executable tools are callable only after their real sandboxed tests pass.

## Execution isolation

Actors keep the previous macOS whole-client Seatbelt isolation: only their own
task folder is writable, corpus/current adapter are read-only, and only their
own controller relay TCP port is reachable. The relay forwards model calls only
to fixed Fireworks inference. It also serves a fixed local MWM executable bridge;
this local route makes no internet requests and cannot select arbitrary mounts.

Learned tools execute through the upstream Linux PythonSandbox in an ephemeral
networkless local container. Only the current adapter is mounted read-only;
no corpus, official answers, host checkout, secrets or Docker socket is mounted.
The actor never receives Docker access. The container image is pinned by digest.
This executable bridge is new infrastructure, not an unmodified upstream macOS
capability. No example-specific feedback is supplied by that infrastructure.

Learner commands use the native folder/network sandbox with explicit document
read grants. The whole repository is excluded from runtime read grants because
it may contain private run directories. Commands cannot change the protected
core, Git metadata, scoring or policy. Only its candidate/scratch are writable.

## Scoring and interpretation

All 100 original predictions are sealed before the pinned official grader runs.
Strict numeric tolerance 0 is primary; 1% is secondary. No LLM judge. Round 10,
after Q50, cannot affect this run's scores. Failed attempts stay in the denominator.
This compares two treatments within this run. Multiple settings differ from the
prior bounded memory-only experiment, so cross-run changes cannot be attributed
to any one setting. The adapted arm receives additional compute and past answers.
Costs and unknown usage are recorded, not constrained. No paid score is claimed
by packaging, preflight or synthetic tests.
